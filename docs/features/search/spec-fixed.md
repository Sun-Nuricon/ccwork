# spec-fixed: 노트 검색 (search)

> 단계 1 산출물. 요구사항 인터뷰로 모호성을 제거한 구현용 명세.
> 이 문서가 이후 PRD·이슈 분해의 기준이 된다.

## 한 줄 요약

사이드바에 검색 입력을 두어, 입력한 키워드로 **제목 + 본문**을 실시간 필터링해
노트 목록을 좁힌다.

## 용어 정의 (Ubiquitous Language)

| 용어              | 정의                                                                |
| ----------------- | ------------------------------------------------------------------- |
| 검색어(query)     | 사용자가 검색 입력란에 타이핑한 문자열.                             |
| 검색 대상(scope)  | 검색이 들여다보는 노트 필드 = `title` + `content`.                  |
| 매칭(match)       | 검색어가 노트의 제목 또는 본문에 부분 문자열로 포함되는 것.         |
| 필터링(filtering) | 매칭되는 노트만 사이드바 목록에 남기는 동작. 데이터 자체는 안 바뀜. |
| 결과 없음         | 노트는 존재하지만 검색어에 매칭되는 노트가 0개인 상태.              |

## 확정된 결정 (인터뷰 결과)

| #   | 항목           | 결정                                                        |
| --- | -------------- | ----------------------------------------------------------- |
| 1   | 검색 대상 필드 | **제목(title) + 본문(content) 둘 다**                       |
| 2   | 실행 방식      | **실시간 필터링** — 타이핑 즉시 목록 갱신 (버튼/엔터 없음)  |
| 3   | 하이라이트     | **하지 않음** (v1 제외, Out of Scope) — 목록 필터링만       |
| 4   | 선택 노트 동작 | 검색으로 걸러져도 **편집기는 그대로 유지** (선택 상태 불변) |

## 기본값으로 확정한 저강도 항목

별도 이견이 없어 추천 기본값으로 고정한다. PRD에서 뒤집을 수 있다.

- **매칭 규칙**: 대소문자 무시 + 부분 문자열 포함 (`text.toLowerCase().includes(query.toLowerCase())`).
  형태소 분석·퍼지 매칭·정규식은 하지 않는다.
- **검색창 위치**: 사이드바(`NoteList` 영역) **상단**, 노트 목록 위.
- **빈/공백 검색어**: `query.trim()`이 빈 문자열이면 필터링하지 않고 **전체 목록**을 보여준다.
- **결과 없음 UI**: 한국어 안내 문구(예: `"검색 결과가 없습니다"`)를 인라인으로 렌더.
  기존 빈 상태(`"노트가 없습니다"`)와는 별개 메시지.
- **검색어 초기화**: 입력란을 비우면(또는 clear 동작) 즉시 전체 목록 복귀.
  별도 X 버튼은 PRD에서 UI 설계 시 결정.

## 최소 동작 시나리오 (3개)

1. **기본 검색**: 사용자가 검색창에 `react`를 입력하면, 제목 또는 본문에 `react`(대소문자
   무시)가 포함된 노트만 사이드바에 남는다.
2. **결과 없음**: 매칭되는 노트가 하나도 없으면 목록 자리에 `"검색 결과가 없습니다"`가
   표시된다.
3. **검색어 비우기**: 검색창을 비우면 즉시 전체 노트 목록으로 돌아온다.

## 경계 조건

- **빈 검색어 / 공백만**: 전체 목록 (필터 미적용).
- **결과 0개**: 결과 없음 메시지.
- **노트 0개(원래 비어있음)**: 기존 `"노트가 없습니다"` 빈 상태 유지 (검색과 무관).
- **선택된 노트가 결과에서 빠짐**: 사이드바에서만 사라지고 편집기는 유지.
- **대소문자**: 무시.
- **앞뒤 공백**: 검색어는 `trim` 후 판정 (단, 단어 중간 공백은 그대로 매칭에 사용).

## 에러 처리

- 검색은 메모리 내 배열 필터링이므로 **네트워크/throw 경로가 없다.** 새 에러 처리 불필요.
- 기존 fetch 에러(`NotesContext.error`)는 그대로 동작 — 에러 상태에서는 목록 대신
  에러 메시지가 뜨므로 검색 UI도 그 흐름을 따른다.

## 기존 코드와의 관계

- 노트는 이미 `NotesContext.notes`에 전부 로드돼 있어 **서버 요청 없이** 클라이언트에서
  필터링 가능 (json-server `q` 파라미터 불필요).
- 검색어는 "어느 노트가 선택됐는가"와 같은 **UI 전용 로컬 상태** 성격 → Context가 아닌
  컴포넌트 `useState`로 두는 것이 기존 상태 분리 원칙에 부합 (구체 위치는 PRD에서 결정).
- `Note` 타입 변경 없음. `api/notes.ts` 변경 없음(클라이언트 필터링 시).

## Out of Scope (이번에 하지 않을 것 — PRD에서 확정 예정)

- 매칭 텍스트 하이라이트(`<mark>`)
- 서버사이드 검색 / json-server `q` 파라미터 사용
- 태그 기반 검색 (tags 필드 자체가 아직 없음)
- 퍼지 검색·정규식·형태소 분석·검색어 자동완성/추천
- 검색 결과 정렬·랭킹(관련도순)
- 검색 기록(history) 저장
