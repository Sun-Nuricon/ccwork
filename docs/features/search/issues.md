# 이슈 분해: 노트 검색 (search)

> 단계 3 산출물. PRD를 실행 가능한 작업 단위(수직 슬라이스)로 분해.
> 기준 입력: [prd.md](./prd.md) — 안 B (검색어를 `App.tsx` 로컬 state로)

## 수직 슬라이싱 점검

- 검색 **input + 필터링 로직은 한 이슈로 묶는다.** input만 만드는 이슈는 사용자에게
  보여줄 동작이 없어 수평 슬라이스가 되므로 금지.
- 각 이슈는 완료 시 사용자에게 보여줄 동작이 있고, 독립적으로 TDD 사이클을 돌릴 수 있다.

## 이슈 목록

### 이슈 1 — 제목·본문 실시간 검색 필터링

**가치**: 검색창에 키워드를 입력하면 제목·본문에 매칭되는 노트만 사이드바에 남는다.
이 이슈만 끝나도 "검색"이라는 핵심 가치가 완성된다.

**범위**

- `SearchInput` 컴포넌트 추가(사이드바 상단, 한국어 placeholder). named export, `interface
SearchInputProps`. 입력값 제어는 부모가 주입한 `value`/`onChange`로(콜백 주입 패턴).
- `App.tsx`에 `query` 로컬 state 추가(`selectedNoteId`와 동급), 사이드바 영역에 `SearchInput`
  배치, `query`를 `NoteList`에 prop으로 주입.
- `NoteList`가 `query`를 받아 렌더 직전 필터링: `title`/`content`를 소문자화해 부분 문자열
  매칭. `query.trim()`이 비면 전체 노트.
- 매칭 판정은 순수 함수로 분리(예: `matchesQuery(note, query)`)해 단위 테스트 가능하게.
- **목록 카운트 반영**: `NoteList` 상단 "노트 N개"의 N은 필터링된(보이는) 노트 수로 표시.
- **선택 상태 불변**: 검색은 `NoteList` 표시만 거른다. `selectedNoteId`·`NoteEditor`는
  건드리지 않는다(ADR-1 확정 사항).

**의존성**: 없음 (첫 이슈).

## Acceptance Criteria

- [ ] Given 제목에만 키워드가 있는 노트가 있고, When 그 키워드를 입력하면, Then 해당
      노트가 목록에 남는다.
- [ ] Given 본문에만 키워드가 있는 노트가 있고, When 그 키워드를 입력하면, Then 해당
      노트가 목록에 남는다.
- [ ] Given 제목이 "React 정리"인 노트가 있고, When `rea`처럼 일부만 입력하면, Then 부분
      문자열로 매칭되어 목록에 남는다.
- [ ] Given 제목이 "React"인 노트가 있고, When `react`(소문자)로 검색하면, Then 대소문자
      무시하고 매칭된다.
- [ ] Given 본문에 "회의록"이 있는 노트가 있고, When `회의`를 입력하면, Then 한글
      부분 문자열로 매칭된다.
- [ ] Given 키워드가 노트 3개에 걸쳐 있고, When 그 키워드를 입력하면, Then 매칭되는
      3개가 모두 남고 나머지는 목록에서 사라진다.
- [ ] Given 검색창이 비어 있고, When 키워드를 한 글자씩 입력하면, Then 버튼·엔터 없이
      입력 즉시 목록이 갱신된다(실시간).
- [ ] Given 검색으로 목록이 좁혀진 상태에서, When 검색창을 비우면, Then 전체 노트가 다시
      보인다.
- [ ] Given 공백만 입력하면, When 필터가 적용될 때, Then 전체 노트가 그대로 보인다.
- [ ] Given 검색으로 2개가 매칭된 상태에서, When 목록을 보면, Then "노트 2개"처럼 카운트가
      필터링된 개수를 표시한다(전체 개수가 아님).
- [ ] Given 어떤 노트를 선택해 편집기에 띄운 상태에서, When 그 노트가 빠지는 검색어를
      입력하면, Then 사이드바에서는 사라지지만 편집기에는 그 노트가 그대로 유지된다.

### 이슈 2 — 검색 결과 없음 빈 상태

**가치**: 매칭되는 노트가 0개일 때 "검색 결과가 없습니다"를 보여줘, 사용자가 빈 화면에
당황하지 않는다. 원래 노트가 없는 상태("노트가 없습니다")와는 구분되는 별도 메시지.

**범위**

- `NoteList`에서 필터 결과가 0개이고 `query.trim()`이 비어있지 않을 때, 한국어 안내
  문구를 early return으로 렌더(기존 빈/로딩/에러 early return 패턴 따름).
- 원래 노트가 0개인 경우(`notes.length === 0`)의 기존 "노트가 없습니다"는 그대로 유지.
- 결과 없음일 때 카운트 헤더("노트 N개")는 표시하지 않는다(메시지로 대체).

**의존성**: 이슈 1 (검색 input·필터링이 존재해야 함).

## Acceptance Criteria

- [ ] Given 노트가 있지만, When 어느 노트와도 매칭되지 않는 키워드를 입력하면, Then "검색
      결과가 없습니다"가 표시된다.
- [ ] Given "검색 결과가 없습니다"가 보이는 상태에서, When 검색창을 비우면, Then 전체 노트
      목록으로 돌아간다.
- [ ] Given 노트가 1개 이상 있고 검색 결과가 0개일 때, When 메시지를 보면, Then "검색
      결과가 없습니다"이며 기존 "노트가 없습니다"와는 다른 문구다.
- [ ] Given 원래 노트가 0개인 상태에서, When 검색창이 비어 있으면, Then 기존 "노트가
      없습니다" 메시지가 보인다(검색 결과 없음 메시지가 아님).

## 의존성 순서

```
이슈 1 (검색 필터링)  →  이슈 2 (결과 없음 빈 상태)
```

이슈 1이 input·필터링·`query` 배선을 만들고, 이슈 2가 그 위에 0건 분기만 얹는다.
역방향 의존 없음.
