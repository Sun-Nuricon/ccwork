# Security Review

REFACTOR(`tdd-refactor`)까지 끝낸 변경을 **커밋하기 직전**에 점검하는 게이트. 세 가지를
스캔하고(타입 오류·의존성 취약점·환경변수 노출), 결과를 **분류**해 보고한 뒤, 승인된
"즉시 수정 필요"만 고친다. TDD 사이클의 마지막 안전 점검이며, 통과하면 커밋으로 간다.

입력은 이슈 번호 하나(`$ARGUMENTS`)다 — 어떤 변경을 검토하는지의 맥락이다.

> **이 스킬의 본질**: 스캐너는 신호를 줄 뿐, 무엇을 고칠지는 판단이다. 모든 경고를
> 기계적으로 고치면 멀쩡한 코드를 망치고(특히 `audit fix --force`), 다 무시하면
> 게이트가 무의미하다. 그래서 **분류 → 승인 → 최소 수정**이 이 스킬의 골격이다.

## 절대 제약

1. **판단이 필요한 항목은 반드시 개발자 승인 후 수정.** 스캐너 결과는 false positive와
   의도된 패턴이 섞여 있다. 자동으로 고치지 않는다 — 분류해 보고하고 멈춘다(4단계 게이트).
2. **테스트 파일 수정 금지.** `*.test.ts` / `*.test.tsx`는 명세다. 타입 오류가 테스트에서
   나도 테스트를 고쳐 무마하지 않는다(원인이 구현/타입이면 거기를 고친다).
3. **`npm audit fix --force` 금지.** `--force`는 **메이저 버전을 멋대로 올려** 동작을
   깨뜨린다. 취약점은 분류해 보고하고, 고친다면 명시적·범위 한정으로만(아래 5단계).
4. **승인된 "즉시 수정 필요"만 처리.** "권장"·"무시 가능"은 이 스킬에서 손대지 않는다
   (권장은 별도 작업, 무시 가능은 근거만 남긴다).

## Workflow

순서대로 진행한다. **4단계 분류 보고 → 승인 게이트**가 핵심이다.

### 1. 타입 점검

```bash
npx tsc --noEmit
```

- 빌드(`npm run build`)는 `tsc && vite build`라, 타입 오류는 곧 **빌드 실패**다.
  그래서 타입 오류는 기본적으로 "즉시 수정" 후보다.
- 출력의 오류를 `파일:라인 — 메시지` 형태로 수집한다. 0개면 "타입 클린"으로 기록.

### 2. 의존성 취약점 점검

```bash
npm audit
```

- 심각도(critical/high/moderate/low)와 패키지·경로를 수집한다.
- **맥락을 본다**: 이 프로젝트는 학습용이고 `json-server`·빌드 도구 등 **devDependencies**가
  취약점 대부분을 차지할 수 있다. 런타임(프로덕션 번들)에 들어가는 의존성의 취약점과,
  로컬 개발에서만 쓰는 도구의 취약점은 위험도가 다르다 — 분류에 반영한다.
- `npm audit --json`으로 받아 심각도별 집계를 정확히 해도 좋다.

### 3. 환경변수 노출 점검

`.env`의 비밀값이 `src/` 코드에 **직접 노출**되는지 확인한다.

- `.env`/`.env.local` 등이 있으면 변수명을 추출하고, 그 이름이나 값이 `src/`에
  하드코딩돼 있지 않은지 grep 한다.
- **Vite 특성(중요)**: Vite는 **`VITE_` 접두 변수만** 클라이언트에 노출하고, 그 값은
  빌드 시 **번들에 그대로 박혀 브라우저로 전송**된다. 따라서 비밀키를 `VITE_`로
  노출하면 그 자체가 유출이다. `import.meta.env.VITE_*` 사용처와, 비밀로 보이는
  하드코딩 문자열(토큰/키/시크릿)을 함께 본다.
- 점검 예시:
  ```bash
  # src에서 비밀스러운 하드코딩/직접 참조 패턴 탐색
  grep -rnE "(api[_-]?key|secret|token|password|process\.env|import\.meta\.env)" src/
  ```
- `.env`가 없고 하드코딩 비밀도 없으면 "환경변수 노출 없음"으로 기록한다.
- 참고: 이 프로젝트의 API URL은 `src/api/notes.ts`에 `localhost`로 하드코딩돼 있는데,
  이건 비밀이 아니라 의도된 로컬 설정이다 — "무시 가능"으로 분류한다.

### 4. 결과 분류 → 보고 → 승인 대기 〈게이트〉

수집한 모든 결과(타입·취약점·환경변수)를 **세 가지로 분류**해 보고하고 멈춘다.
승인 없이 코드를 바꾸지 않는다.

- **🔴 즉시 수정 필요** — 보안 위험 또는 빌드 실패 수준. 예: 타입 오류(빌드 깨짐),
  런타임 의존성의 high/critical 취약점, 비밀키의 `src/` 하드코딩·`VITE_` 노출.
- **🟡 권장 수정** — 코드 품질 저하지만 당장 위험하진 않음. 예: dev 전용 의존성의
  moderate 취약점, 패치 가능하나 영향 작은 항목.
- **⚪ 무시 가능** — false positive 또는 의도된 패턴. 예: `localhost` 하드코딩,
  업스트림에 픽스 없는 transitive 취약점, 학습용이라 수용된 위험. **왜 무시해도
  되는지 근거를 반드시 적는다**(나중에 다시 의심하지 않도록).

보고 형식(항목별 한 줄):

```
🔴 [타입] src/components/NoteEditor.tsx:42 — 'tags' is possibly undefined (빌드 실패)
🟡 [취약점] esbuild <0.25 moderate (dev 의존성, 런타임 영향 없음) — 패치 가능
⚪ [환경변수] src/api/notes.ts:1 localhost 하드코딩 — 의도된 로컬 설정, 비밀 아님
```

- 분류 근거(심각도·런타임 여부·노출 경로)를 함께 적는다.
- 개발자가 일부만 승인할 수 있다. **승인된 "즉시 수정 필요"만** 5단계로 간다.
- 🔴이 하나도 없으면 "클린"을 보고하고 6단계(재스캔 생략 가능)로 — 커밋 진행 가능 안내.

### 5. 승인된 "즉시 수정 필요"만 처리

- 타입 오류: 원인(구현/타입 정의)을 고친다. 테스트를 고쳐 무마하지 않는다.
- 취약점: `--force` 없이 범위를 한정해 처리한다. 가능한 경우만:
  ```bash
  npm audit fix            # 동작 안 깨는 범위(semver 호환)에서만 수정
  npm install <pkg>@<ver>  # 특정 패키지만 안전 버전으로 명시 지정
  ```
  메이저 업그레이드가 필요하면 그건 "승인+별도 검증"이 필요한 일 — 자동으로 하지 말고
  보고한다.
- 환경변수 노출: 비밀을 `src/`에서 제거하고 `.env`(+`import.meta.env`)로 옮기거나,
  애초에 클라이언트에 있으면 안 되는 값이면 서버 측으로 옮길 것을 제안한다.
- **한 항목 고칠 때마다 `npm test`로 회귀를 확인한다**(REFACTOR와 같은 안전 원칙).

### 6. 재스캔 → 클린 확인

수정한 카테고리를 다시 돌려 깨끗해졌는지 확인한다.

```bash
npx tsc --noEmit        # 타입 0 오류
npm audit               # 처리한 취약점 해소(남은 건 분류대로)
npm test                # 회귀 없음
```

- "즉시 수정 필요"가 모두 해소되고 테스트가 초록이면 커밋 가능 상태다.
- 남은 🟡/⚪ 항목은 분류·근거와 함께 요약에 남긴다(고치지 않은 게 정상).

### 7. 요약 보고

- 스캔 3종 결과와 분류(🔴/🟡/⚪ 개수).
- 처리한 🔴 항목과 전/후, 재스캔 결과(클린 확인).
- 남긴 🟡/⚪ 항목과 그 근거.
- 다음 단계: 커밋 진행 안내.

## 분류 판단 기준 (헷갈릴 때)

- **빌드를 깨뜨리는가?** → 타입 오류는 거의 항상 🔴.
- **프로덕션 번들/런타임에 들어가는가?** → 런타임 의존성 high/critical은 🔴, dev 전용
  moderate 이하는 보통 🟡.
- **비밀이 클라이언트로 나가는가?** → `VITE_`로 노출되거나 `src/`에 하드코딩된 진짜
  비밀은 🔴. `localhost`·공개 가능한 설정은 ⚪.
- **업스트림에 픽스가 있는가?** → 없으면(고칠 수 없으면) ⚪로 근거와 함께 보류.
- 애매하면 **더 높은 위험으로 올려 분류하고 개발자 판단에 맡긴다**(게이트의 목적).

## 하지 않는 것 (범위 밖)

- **승인 없는 수정** — 4단계 게이트를 건너뛰지 않는다.
- **`npm audit fix --force`** — 메이저 강제 업그레이드로 동작을 깬다.
- **테스트 파일 수정** — 명세는 고정.
- **권장/무시 항목 수정** — 🟡은 별도 작업, ⚪는 근거만.
- **여러 이슈 동시 처리** — 한 번에 이슈 1개.
- **커밋 자체** — 이 스킬은 "커밋해도 되는 상태"를 만들고 끝낸다(커밋은 별도).

## 도구 메모

- 타입: `npx tsc --noEmit` (빌드 전 타입만 검사, 산출물 없음).
- 취약점: `npm audit` / 집계는 `npm audit --json`. 수정은 `npm audit fix`(=`--force` 금지).
- 환경변수: `.env*` 변수명 추출 후 `grep -rn` 으로 `src/` 노출 확인. Vite는 `VITE_`
  접두만 클라이언트로 내보내고 번들에 박힌다는 점을 기억.
- 회귀 확인: `npm test`(= `vitest run`). 맥락 소스는 `CLAUDE.md` + `docs/features/tag/issue-{N}.md`.
